# 多模态 RAG 检索效果分析报告

> 数据来源：`rag_eval.py` 于 2026-09-15 对向量库（61 条真实图片）跑的 11 条 query，
> 含 `retrieval`（本地复刻生产检索链路）+ `e2e`（请求 Docker 中 `/api/chat` 全链路）双模式，开启 rerank 前后对比。
> 原始明细见 `rag_report.md` / `summary.json`。

---

## 一、结论速览

| 维度 | 纯向量检索(MMR) | +rerank 重排 | e2e 全链路 |
|------|:---:|:---:|:---:|
| 平均 Top1 命中率 | 60% | **80%** | **80%** |
| 平均 MRR | 0.71 | **0.88** | 0.85 |
| 平均 Recall | 0.71 | — | 0.73（受返回数截断）|
| 负样本误召 | 0/1（相似度 0.43 < 阈值 0.55）✓ | — | 无阈值门控，仍返回 3 张 ⚠ |

**三句话总结：**
1. **语义/场景/口语化描述类检索近乎完美**——6 条单目标 query 在纯检索和 e2e 下 **Top1 命中率均 100%、MRR 1.0**。
2. **qwen3-vl-rerank 重排价值显著且可量化**——整体 MRR 从 0.71→0.88（+24%），Top1 从 60%→80%（+20pp），对纯向量几乎漏召的专名查询有"起死回生"效果。
3. **两个诚实短板**——以图搜图"同角色"失效；e2e 无相关度阈值门控（对库外查询仍硬返回 Top-N）。

## 二、测试设置与口径

- **向量库**：Chroma `picture_vectors`，61 条真实图片（本地 `agent/app/chroma_data`，与容器内置为同一批）。
- **嵌入/重排模型**：`qwen3-vl-embedding`（`enable_fusion=True`）+ `qwen3-vl-rerank`，与生产完全一致。
- **检索链路复刻**：文本走 MMR（`k=expected_count×10, fetch_k=max(k×2,20), lambda_mult=0.5`）；图搜走 `_collection.query` 直查——均与生产节点参数一致。
- **Top-K = 10**；e2e 每条 query 新建 thread，避免上下文污染。
- **相关集(Ground Truth)**：按 `name/introduction/tags` 关键字子串匹配圈定（脚本已打印，见 `rag_report.md` 第一节）。

> ⚠️ **Precision@K 口径说明**：本次平均 Precision@10 仅 0.16，**这不代表质量差**。因为库仅 61 张、多数 query 的相关图只有 1~8 张，用 K=10 去算精确率会被"库里没有更多相关图"结构性惩罚。**本场景应以 Top1 / MRR / Recall 为准，Precision@K 不具参考意义。**

## 三、核心发现（分类型）

### ✅ 发现 1：描述/场景/口语类单目标检索 = 满分
| query | 类型 | 纯检索 Top1/MRR | e2e Top1 |
|-------|------|:---:|:---:|
| 找拿着烈酒、甩辫子的二次元角色 | 外观属性 | ✓ / 1.00 | ✓ |
| 找海边约会的少女 | 场景 | ✓ / 1.00 | ✓ |
| 找夜晚的城市街景 | 场景 | ✓ / 1.00（3张全中）| ✓ |
| 找学校的夕阳 | 场景 | ✓ / 1.00 | ✓ |
| 那张竖小指的动漫表情包 | 口语 | ✓ / 1.00 | ✓ |
| 摩天轮上的心动瞬间 | 口语 | ✓ / 1.00 | ✓ |

**6/6 全中**。说明 `qwen3-vl-embedding` 的多模态融合向量对"用自然语言描述画面内容/氛围/梗"这类查询理解到位——**这正是本项目 RAG 的核心卖点**。尤其"竖小指""摩天轮心动"这类**口语/比喻**查询也能 Top1 命中，证明嵌入模型抓的是语义而非字面。

### ⭐ 发现 2：rerank 的"起死回生"——专名查询案例
最有说服力的一条：**T1-02「搜井芹仁菜的图」**
- 纯 MMR 检索：目标图排在**第 13 位**，MRR 仅 **0.08**，Top10 内 0 命中（几乎漏召）。
- 经 `qwen3-vl-rerank` 重排后：**直接拉到第 1 位**，MRR **1.00**（ΔMRR **+0.92**）。
- e2e 全链路同样 Top1 命中。

**根因**：目标图 `井芹仁菜【新春限定】` 简介为空，MMR 在向量空间里受多样性打散影响被挤到后面；而 rerank 模型读取"名称+图片"做交叉语义比对，精准识别出专名匹配。**这条完美论证了"向量召回 + 重排"两阶段架构的必要性。**

类似地 **T4-01「二次元壁纸」**：纯检索 MRR 0.50 → rerank 后 1.00（+0.50）。

### ⚠️ 发现 3：以图搜图"同角色"是明确短板
**I1-01**（用"486壁纸"图搜同角色安和昴）：
- 报告中 `最高相似度 0.82` 是**查询图自身**的匹配分（剔除自身前），**不代表召回质量**。
- 剔除自身后：纯检索 Top1 ✗、Recall@10 仅 0.33（6 张同角色只召回 2 张）、MRR 0.25；**rerank 无改善**（ΔMRR 0.00）。
- e2e 更差：返回的是"艾玛系列""4"等**完全不同角色**，Recall = 0。

**根因**：`qwen3-vl-embedding` 的图像向量更偏"视觉风格/构图相似"，而非"同一人物身份"。同角色的不同立绘在视觉向量上并不聚拢。**结论：以图搜图适合"找相似风格/场景"，不适合"找同一角色"——后者应靠 tag/角色名文本检索。**

### ⚠️ 发现 4：e2e 缺少相关度阈值门控
**T6-01 负样本「找几张真实猫咪的照片」**：
- 纯检索层表现正确：最高相似度 0.43 < 阈值 0.55，**没有强命中**（有区分度）。
- 但 e2e 仍**硬返回 3 张**（安和猫、芝士雪豹…）。

两点结论：
1. 本负样本选得不够"干净"——库里其实有"安和猫""芝士雪豹"等动物图，返回它们不算全错；
2. 但暴露一个**产品级改进点**：e2e 链路无论相关度高低都会返回 Top-N，**缺少"低于阈值则回复'没找到相关图片'"的门控**，真实库外查询会有幻觉式返回风险。

### 🔧 发现 5：expected_count 未遵循用户显式数量
「找**5 张**安和昴的图」e2e 实际只返回 **3 张**（全部 query 都固定返回 3）。说明查询重写/`expected_count` 解析没吃到用户明示的数量，或 rerank `top_n` 默认锁死为 3。**属可优化的小问题**（影响 Recall 上限，不影响排序质量）。

### 📝 发现 6：Ground Truth 标注存在 gap（不影响主结论）
T1-01「安和昴」e2e 返回的首图是"**安和猫**"，因关键字规则只认"昴/Subaru"，被判为 ✗。但"安和猫"很可能本就是该角色的相关图。**即专名多图查询的真实 Top1 命中率可能被低估**。这提示：多相关目标的 query，人工标注相关集要更完整。

## 五、改进建议（按性价比排序）

1. **e2e 加相关度阈值门控**（高性价比）：rerank/检索最高分低于阈值时，回复"未找到足够相关的图片"，消除库外查询的幻觉返回。
2. **以图搜图改走"图+角色tag"混合**：纯视觉向量不擅长同人物聚类，建议以图搜图时结合候选图的角色 tag 做过滤/加权，或明确产品定位为"找相似风格"。
3. **expected_count 解析用户显式数量**："找 N 张"应驱动 `top_n`，提升 Recall 上限与体验一致性。
4. **补全图片元数据**：61 条中约 37 条 `introduction/category` 为空、`name` 为时间戳，纯靠视觉向量兜底；补齐文本元数据可显著提升专名/属性类召回（T1-02 的漏召正源于简介为空）。
5. **多相关目标 query 的人工标注**：完善 Ground Truth，避免低估真实命中率。

## 六、简历/汇报可用的量化结论（均基于本次实测）

- 构建**多模态 RAG 图片检索**（`qwen3-vl-embedding` 融合向量 + Chroma + `qwen3-vl-rerank` 两阶段），在真实图片库上对**自然语言描述/场景/口语化查询的 Top1 命中率达 100%、MRR 1.0**（6/6）。
- 设计并落地 **rerank 重排阶段**，使整体检索 **MRR 从 0.71 提升至 0.88（+24%）、Top1 命中率从 60% 提升至 80%（+20pp）**；对纯向量召回近乎漏召的专名查询（原始排名第 13、MRR 0.08）**重排后拉升至第 1（MRR 1.0）**。
- 搭建**可复现的 RAG 自动化评测脚本**（retrieval + e2e 双模式、Ground Truth 自动解析、Recall@K/MRR/Top1/负样本误召等指标 + Markdown 报告），支撑检索效果的量化回归。
